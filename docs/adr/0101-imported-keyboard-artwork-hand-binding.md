# ADR-0101: 导入键盘模型按键位图目录绑定手侧

状态：已接受（2026-11-07）
依赖：ADR-0042（缺图不触发）、ADR-0070（手柄按键图层）

## 问题

导入模型沿用预置键盘的静态手侧：主键区归左手，方向键归右手。按键只检查指定侧的图，
导致把 H、J、数字 6、Enter 等放在 `right-keys` 的分手键盘模型无法响应这些按键。
小熊猫昊昊键盘模型提供 28 张左手图和 32 张右手图，原实现只让右手四个方向键可达。
ADR-0042 的残余风险 1 描述了这个限制。

## 决策

- 仅调整 `ModelOrigin::Installed` 的键盘绑定，覆盖既有完整键位词表，包括修饰键、
  F1–F24、小键盘与 Apple 地球键。
- 使用现有 `KeyImageInventory::can_draw` 与渲染器共用的候选回退规则查找左右目录。
- 先检查原有手侧（方向键右手，其余左手），没有可绘制图时再查另一侧。
  两侧都有图时保留原有手侧；两侧均缺图时不绑定，仍然不动爪、不画键位图。
- 预置模型、手柄绑定、鼠标输入与配置结构保持不变。绑定仍在应用激活模型时计算，
  不把手侧决策放进 renderer，也不增加 runtime 的图片依赖。

本决策替代 ADR-0042 残余风险 1 对导入模型的限制；预置模型的静态绑定仍成立。
不要求重导入模型或修改用户配置。

## 验证与边界

回归用例覆盖分手键盘主键区、反向放置的方向键、同键双侧素材、缺图、共享修饰键与功能键图、
小键盘回退和地球键；原有预置模型契约继续覆盖默认布局。具体执行结果记录在 PR。
Windows/macOS 实机输入、模型观感与长期运行需要独立验证，自动化结果不能替代这些证据。
