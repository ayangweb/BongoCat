# 0086 — 插件的答案唤醒宿主，而不是排队等一次评估

**Status:** accepted

**Amends:** the worker loop in ADR-0079, and the layer-channel paragraph of ADR-0078.

## Context

用户在插件中心改一个配置项，模型窗口「过一会儿」才变。这个延迟不是任何一步的成本，
是等待：宿主的 worker 线程睡在一个**命令通道**上，只有产品发给它的命令能叫醒它；
而插件的回答走的是**另一个进程**的 stdout，落在每个 session 自己的队列里。两条路
从不相遇，于是插件回答得再快，也要等到 worker 结束当前的等待才会被读到。

上限是这个等待本身——`EVALUATION_INTERVAL`，一百毫秒。这是实测的量级，不是估计：
面板在改动后**三毫秒**左右就出现在图层通道上，但 worker 又睡了九十七毫秒才把它取出来。

一百毫秒在聊天窗口里不算长。用户判断一个「原生」面板的依据恰恰是这一点：他按下一个
控件，画面**应该已经**变了。所以要修的不是「把它调小」，而是「等待根本不该存在」。

同一条链路上还有三个独立的浪费，和这个延迟是同一个原因链上的东西：

- **每个面板的像素每次发布都被复制并哈希一次。** `to_raster()` 把整块像素拷进一个
  `Arc` 并计算内容哈希；`publish_layers` 每轮调用两次，worker 每秒跑十轮。一个一秒才
  变一次的倒计时面板因此每秒被复制和哈希二十次，全部发生在**所有插件共用的那一个线程**上。
- **快照里每个位置被算了两遍。** 一张卡片需要自己的位置和可移动位置的菜单，两者都是
  同一次分配的回答；而两个 helper 各自调用 `placements()`。九张卡片加目录里九项，就是
  每发一次快照三十六次全量分配与遍历。
- **模型请求读两次 runtime 快照。** 「窗口可见吗」和「这个模型有这个动作吗」是同一
  时刻的两个问题，分两次读就允许模型在两次读之间换掉。

还有一个 bug 是同一个「迟到即无人处理」的形状，而且比延迟严重：**气泡从未被画出来过。**
worker 统计了它、回答了 `Done`、把它的文本和寿命存了下来，而图层通道要的是像素。
`Host::bubble(...)` 因此是一个成功的空操作：番茄钟结束时那句「本轮结束」，插件相信自己
显示出来了，用户从来没有看见。没有崩溃、没有日志、也没有任何一条不看像素的测试会发现。

## Options considered

### A. 把评估间隔调小

十毫秒或五毫秒。**否决。** 它把「等待」换成「更频繁地醒来」，而醒来的每一轮都要为每个
插件做一次光栅化判断。四个空闲插件在二十毫秒一次的间隔上是每秒五十次无用轮转，换来
的是一个仍然存在的等待——只是从 100 毫秒变成 20 毫秒。用轮询频率换取延迟，代价乘以插件数。

### B. 让命令通道也承载插件的消息

把 `PluginMessage` 塞进 `PluginCommand`，用枚举标签区分。**否决。** 这会让 worker 的
单一入队在类型上同时是「产品的意图」和「插件的陈述」：一个来自进程的文档获得产品命令
的优先级，一个按键和一个 `Shutdown` 排在同一个有界队列里互相挤掉。而且它没有解决
问题本身——命令通道仍然只是被等待的那一个，只是多了一种能叫醒它的消息。

### C. 一个 inbox，两种到达 — chosen

一个 `Mutex` 加一个 `Condvar`，两种东西在里面：

- **命令**是队列，有界，满则丢弃，先进先出。语义与它替换掉的 channel 完全一致：产品侧
  的发送者永远不阻塞在一个正在下载的 worker 上，丢掉的命令是一个没有注册的点击。
- **插件的回答**是一个 flag，没有载荷。载荷已经在 session 自己的队列里了，再复制一份
  就是每条消息在去 worker 的路上多一次拷贝。十个插件同时说话也只是一个布尔值，因为
  「有没有活」这个问题不取决于有几场对话产生了它。

两者一起被等待，所以**每一次真实的唤醒都是事件本身**：一次按键、一次配置修改、一次目录
刷新、插件的一个面板、插件的一次退出。剩下 `EVALUATION_INTERVAL` 的只有时钟驱动的
tick，而 tick 本来就被 `MAXIMUM_TICK_INTERVAL` 单独约束着——一百毫秒从一个「节拍」
退回成「漏掉一次唤醒的最坏时长」。

### D. 每个 session 一个等待对象

worker 对每个 session 各等一次，用 `poll` 之类的多路复用。**否决。** 它需要一个
跨平台的多路复用依赖（`AGENTS.md` §6 的决定阶梯在标准库之前就停了），并且把一个简单
的事实复杂化：所有会话共用一个队列就够了，因为答案不需要带身份——worker 醒来后自己遍历。

## Decision

### 插件的回答唤醒 worker

`signal::Inbox` 是 worker 唯一的等待点。每个 session 的 reader 线程在把一条消息放进
自己的队列**之后**设置那个 flag——顺序是承重的：flag 的含义是「有东西可读」，先设 flag
再入队会造出一个 worker 醒来却读不到东西的轮次，而那一行就会等到下一次评估。

`EVALUATION_INTERVAL` 与 `IDLE_EVALUATION_INTERVAL` 保留，但都变成**上限**而不是节拍。
后者从「直到被叫醒」改为一个小时，因为「永不醒来」会把一次漏掉的唤醒变成一个直到下次
启动才活过来的 worker，而一小时的沉默仍然只是一分钟。

### 光栅化一次，发布多次

`Session` 在 `accept_panel` 里就把 `RenderedPanel` 转成 `OverlayLayerRaster` 并存下；
`publish_layers` 只读引用。气泡同理，在被**请求的那一刻**光栅化并随文本一起存下。

因此发布路径上一次像素都没有被复制。它仍然是「每轮发布一次」而不是「变化时发布一次」，
这是有意的：通道是 latest-wins，跳过发布只是把一次「这里该检查一下」换成一类
「忘了打标记所以没人告诉用户」的 bug，而这个 bug 不可能在任何局部测试里被发现。

### 位置分配一次

`entries()` 算一次 `Placements`，交给两个 helper。分配本身是纯函数，所以两次算出来
不会不一致；但它省掉的是每发一次快照三十六次全量遍历——而快照是在每次握手、每次崩溃、
每次控件改名、每次配置修改时发布的。

### 模型请求读一次快照

可见性与模型词表来自同一次 `client.snapshot()`。这不只是省一次读：分两次读允许模型在
它们之间换掉，于是一个请求可能被回答成「这个模型没有这个动作」，而它有。

### 气泡替换面板，占用它自己的那一层

气泡不是画在面板旁边或上面，而是**在它显示期间占用该插件自己的图层**；它到期时面板立刻
被重新发布。两个插件仍然可以同时各有气泡，因为图层是每个插件一份。

放在设备空间**顶部居中**而不是角落：一条关于刚刚发生的事的句子属于眼睛已经所在的位置。

气泡的生命周期由**宿主**强制，并且**每一轮循环都检查**，不只在有插件运行的那些轮。
这曾是一个 bug：切换掉一个正在显示气泡的插件，会让气泡留在模型窗口上直到会话结束，
因为检查它的代码在一个只有在插件运行时才执行的分支里，而那里已经没有任何东西会叫醒
worker。session 消失时它自己的气泡也被撤下——一个没有主人的图层比一个过期帧更糟。

## Consequences

- `bongocat-plugin::signal` 是新的，一个 `Mutex` 加一个 `Condvar`，没有依赖。`Inbox` 和
  `Wake` 从 `bongocat-plugin` 导出，因为测试需要直接构造它们。
- `Session::start` 多一个参数：一个能说「我这里有东西」的句柄。
- `EVALUATION_INTERVAL` 的含义变了。它不再是延迟的下界，而是一个上限；把它调小不再会
  改善任何用户可见的东西，把它调大也不会让面板变慢。
- `a_change_reaches_the_model_window_without_waiting_for_a_tick` 是一个**计时**的测试，
  预算取旧下界的一半。松紧之间是有理由的：更紧会变成对运行它的机器的测试，更松则旧行为
  在任何机器上都可能蒙混过关——因为旧的延迟是一个定时器而不是一次竞赛。
- 旧的两条「drain 之后立刻 publish」的路径被删掉了，因为它们**与插件赛跑**：一个
  drain 在插件有可能回答之前就跑完了。等待它的正是这条唤醒路径。
- 气泡现在真的会出现在模型窗口上。番茄钟的结束提示、按键提示的 chip、任何
  `Host::bubble` 都可见了；这是一个用户可见的 bug 修复，写进 CHANGELOG。
